# PRD：私域运营团队AI赋能培训（2026年5月）

| 项目 | 内容 |
|:---|:---|
| 文档版本 | v1.0 |

| 负责部门 | 平台运营统筹 |

## 1. 背景与问题

### 1.1 业务背景
- 团队90%工作时间用于文案攥写（信息流、数字人脚本、直播预热、大课）
- 产研已实现"文案自动生成→运营一键下发"，内容生产环节基本自动化
- 5月绩效新增「内部赋能AI」板块，要求团队建立「洞察→分析→行动」运营闭环

### 1.2 核心痛点

| 痛点 | 真实场景 | 影响 |
|:---|:---|:---|
| AI失忆 & 重复输入 | 每次写文案都要贴一遍背景prompt，长对话后AI失忆 | 效率低，体验差 |
| AI幻觉 & 输出失控 | AI偶尔胡说、违禁词漏掉 | 需大量人工检查，风险高 |
| 输出同质化 | 同一个提示词多次使用，AI输出雷同 | 素材质量下降 |
| 多场景切换混乱 | 信息流/数字人/直播预热格式不同，AI容易混乱 | 输出格式错误 |
| AI能力边界不清 | 想让AI给策略框架、产出成品文案 | 期望落差，失去信心 |
| 工具安全问题 | 免费VPN翻墙中毒 | 信息安全风险 |

### 1.3 前期尝试与失败原因
- 团队曾尝试用AI写文案，但觉得"生成的不好用"后放弃
- **根本原因**：用AI做了AI不擅长的事（创意写作），而没试过AI擅长的事（分析归纳、框架执行）

---

## 2. 目标

### 2.1 总体目标
让私域运营团队从"AI不好用"转变为"AI能帮我干活"，建立可复用的AI工作流。

### 2.2 具体目标

| 目标 | 验收标准 | 截止时间 |
|:---|:---|:---:|
| 每人掌握系统模板法 | 提交1份6要素完整的《个人系统模板》 | 培训当天 |
| 建立数据复盘习惯 | 每周五固定30分钟做AI数据复盘，群里发截图 | 5月末 |
| 完成赋能手册 | 输出《用户洞察与数据复盘AI赋能手册》 | 5月末 |
| 产出标杆案例 | 完成2-3个重点品类的完整案例（画像→分层→复盘→策略） | 5月末 |
| 每人完成1次完整复盘 | 按模板完成至少1次个人品类的周度数据复盘 | 5月末 |

### 2.3 档位定义
- **1.0档**：手册完成，每人完成1次完整的数据复盘
- **1.2档**：团队应用后数据指标提升或案例被复用

## 3. 需求详细说明

### 3.1 培训需求

| 需求项 | 要求 |
|:---|:---|
| 培训对象 | 私域运营团队（文案运营、数据/策略运营） |
| 培训时长 | 1场，约2小时 |
| 培训形式 | PPT演示 + 现场实操（仅PPT，不发放含真实模板的纸质材料） |
| 设计原则 | 不讲技术原理，只讲"怎么用"；不聊Agent架构，只聊"按哪个按钮、输入什么话" |
| 核心方法 | 案例驱动，从真实故事引入，当场产出可复用的个人模板 |

### 3.2 培训内容架构（5板块）

#### 板块一：认知破冰（15分钟）
- **引入案例**：运营小李每天写10条文案，AI还是跑偏
- **核心认知**：AI是"高效执行员"，不是"创意总监"；策略靠人，执行靠AI
- **今日目标**：解决AI失忆、AI胡说、AI重复3个问题

#### 板块二：基础入门（20分钟）
- **核心公式**：你是谁 + 做什么 + 输入什么 + 输出格式
- **现场演示**：坏提示词 vs 好提示词（结构对比，真实案例投屏）
- **学员跟练**：每人按公式写一段提示词开头

#### 板块三：进阶方法（25分钟）
- **系统模板6要素**：身份、用户画像、动作、输出要求、违禁词清单、参考框架/示例
- **加载方式3选1**：DeepSeek「技能」（推荐）/ 快捷短语 / 文档复制
- **4个解决方案**：AI失忆、AI胡说、千篇一律、不会纠正

#### 板块四：实战演练（45分钟）
- **步骤1**：制作个人系统模板（15分钟）
- **步骤2**：双轨实操二选一（文案攥写/数据复盘，15分钟）
- **步骤3**：分享点评（15分钟）

#### 板块五：总结与进阶（5分钟）
- 4件事回顾 + 进阶工具推荐 + 5月使用计划

### 3.3 平台分工需求

| 平台 | 使用场景 | 覆盖人群 | 安全要求 |
|:---|:---|:---|:---|
| DeepSeek | 日常主力：文案、复盘、策略 | 全员 | 不翻墙，培训现场统一使用 |
| Gemini | 进阶补充：长文本分析 | 有条件者 | 需安全翻墙，禁止免费VPN |
| 豆包 | 生图专用：课表、海报 | 需要者 | 国内可用 |
| Claude Code | 高阶自动化：Excel批处理 | 技术好奇者 | 需VS Code环境 |

### 3.4 讲师演示案例需求

**案例1：文案攥写 — 中老年课程营销文案**
- 坏提示词 → 好提示词结构拆解
- 讲师演示流程：加载模板 → 输入变量 → AI输出 → 换角度 → 纠正话术

**案例2：数据复盘 — 唱歌宋5.4直播回捞**
- 真实业务数据对比（本周vs上周）
- 提示词框架拆解（数据分析师角色 + 漏斗分析任务）

**案例3：数据复盘 — 普拉提4.27回捞触达率**
- Agent vs 人工策略对比
- 分层优化动作输出

## 4. 非功能需求

| 类别 | 要求 |
|:---|:---|
| 安全性 | 培训材料不含可直接复制粘贴的完整真实提示词模板；真实案例仅投屏演示 |
| 可及性 | 培训现场统一使用DeepSeek，确保人人可用、不卡网络 |
| 可复用性 | 产出《用户洞察与数据复盘AI赋能手册》，供后续月份复用 |
| 可衡量 | 培训前后统计AI使用率、文案产出效率、数据复盘完成率 |

## 5. 时间计划

| 阶段 | 时间 | 动作 |
|:---|:---:|:---|
| 准备期 | 培训前3天 | 准备演示案例、设计PPT、通知学员提前准备素材 |
| 准备期 | 培训前1天 | 统一AI账号、确认设备网络、准备讲师备用素材 |
| 培训日 | T | 2小时培训 + 当场产出个人模板 |
| 跟进期 | T+3天 | 组长抽查系统模板使用情况 |
| 常态化 | 每周五 | 固定30分钟AI数据复盘 |
| 迭代期 | 每周 | 每人迭代1次系统模板 |
| 收官 | 5月末 | 提交模板终版 + 复盘报告 + 统计培训效果 |

## 6. 验收标准

### 6.1 培训当天验收
- [ ] 每人提交1份6要素完整的《个人系统模板》
- [ ] 每人完成1份实操产出（文案或数据复盘）
- [ ] 产出符合模板约束，纠正话术使用正确

### 6.2 5月末验收
- [ ] 《用户洞察与数据复盘AI赋能手册》输出完成
- [ ] 2-3个重点品类的完整标杆案例（画像→分层→复盘→策略）
- [ ] 每人完成至少1次完整的数据复盘
- [ ] 统计培训前后变化：AI使用率、文案产出效率、数据复盘完成率

---

## 7. 风险与应对

| 风险 | 影响 | 应对策略 |
|:---|:---|:---|
| 学员对AI已失去信心，参与积极性低 | 培训效果打折 | 开场用真实故事共情，先用数据复盘让学员快速感受AI价值 |
| 真实模板外泄 | 运营策略泄露 | PPT-only形式，真实案例仅投屏演示，不留在PPT页面上 |
| 现场网络或账号问题 | 实操环节中断 | 提前1天统一测试DeepSeek账号，准备备用网络方案 |
| 学员基础差异大 | 进度不齐 | 按业务角色分组（文案组/数据策略组），组长巡视答疑 |
